# Embedded / IoT Mentor — یک Skill برای Claude

[English](./README.md) · [Svenska](./README.sv.md) · **فارسی**

<div dir="rtl" align="right">

یک Skill برای [Claude](https://claude.ai) که نقش یک مربی باتجربهٔ سیستم‌های نهفته را بازی
می‌کند: میکروکنترلر، برد و زنجیرهٔ ابزار پروژه را انتخاب می‌کند، هزینه و زمان تقریبی آن را
تخمین می‌زند، و یک نقشهٔ ساخت به شما می‌دهد که روی یک **بردبورد کارکننده** متوقف می‌شود،
نه روی خط تولیدی که هرگز نخواسته‌اید.

بیشتر توصیه‌ها دربارهٔ سیستم‌های نهفته به یکی از دو سمت منحرف می‌شوند: یک فهرست قطعات بدون
نقشه، یا یک مسیر تولید انبوه برای کسی که هنوز یک LED را چشمک‌زن نکرده است. این Skill اول
می‌پرسد واقعاً تا حالا چه ساخته‌اید، بعد در همان سطح جواب می‌دهد.

## نمونهٔ اجرا

<div dir="rtl" align="right">

یک گوسفنددار در دِوون، بدون کدنویسی، شش نقطهٔ اندازه‌گیری که دورترینشان ۴۰۰ متر از خانه
فاصله دارد. ارزش تماشا دارد، به‌خاطر کارهایی که این Skill *نمی‌کند*: از همان ابتدا نیمی از
درخواست را رد می‌کند — هیچ سنسور ارزانی نیتروژن خاک را صادقانه اندازه نمی‌گیرد — و بعد
می‌گذارد سه محدودیت انتخاب‌ها را انجام دهند. ۴۰۰ متر رادیو را به‌جای Wi-Fi انتخاب می‌کند،
«من کد نمی‌نویسم» فریمور آماده را به‌جای زنجیرهٔ ابزار انتخاب می‌کند، و یک مرتع خیس محفظه را
انتخاب می‌کند. برد آخرین چیزی است که تصمیم‌گیری می‌شود، نه اولین چیز. متن کامل گفت‌وگو در
[سناریوی D](./embedded-iot-mentor/examples/worked-examples.md#scenario-d--when-half-the-brief-cannot-be-built)
آمده است.

## چه کاری انجام می‌دهد

- **یک پلتفرم انتخاب می‌کند** — ESP32، Pico، STM32، nRF52 — و صریح می‌گوید چرا همان، به
  همراه یک یا دو جایگزین و اینکه هرکدام در چه شرایطی برنده می‌شود.
- **مسیر سخت‌افزار را از مسیر فریمور جدا می‌کند**، تا بدانید چه باید بخرید و چه باید نصب
  کنید، بدون اینکه این دو با هم قاطی شوند.
- **بررسی می‌کند که اصلاً لازم است فریمور بنویسید یا نه.** اگر ESPHome، Meshtastic یا
  Tasmota همین حالا کار را انجام می‌دهند، جواب همان است — نوشتن کد یک هزینه است، نه یک
  دستاورد.
- **زمان و هزینه را به‌صورت بازه تخمین می‌زند** و می‌گوید چه چیزی واقعاً آن‌ها را بالا
  می‌برد — از جمله هزینهٔ *نگهداری و کارکرد*، وقتی پای شش گره در دل یک مزرعه وسط باشد که
  باتری مصرف می‌کنند.
- **می‌گوید یک سنسور واقعاً چه چیزی را اندازه می‌گیرد.** پروب‌های ارزان «NPK» رسانایی را
  می‌خوانند و بقیه را حدس می‌زنند؛ این را قبل از خرید شش عدد به شما می‌گوید، نه بعد از آن.
- **تا MVP نقشه می‌کشد و همان‌جا می‌ایستد.** مراحل نمونهٔ مهندسی، پیش‌تولید و تولید وجود
  دارند، اما فقط وقتی درخواست کنید ارائه می‌شوند.
- **ریسک‌ها را نام می‌برد** — بودجهٔ توان، موجود بودن قطعات، نبود مسیر اشکال‌زدایی،
  گواهی‌نامه، و منحنی یادگیری همان چیزی که پیشنهاد داده است.
- **پیشنهادهای خودش را رد می‌کند** بر اساس یک معیار ثابت: نبودِ کتابخانهٔ نگهداری‌شده، قطعهٔ
  تک‌تأمین‌کننده، بسته‌بندی‌ای که نمی‌توانید لحیم کنید، نبودِ کنسول سریال — گزینه را کنار
  می‌گذارد و دوباره انتخاب می‌کند.

## چرا وجود دارد

خطاهایی که برای گرفتنشان ساخته شده است:

- **یک تازه‌کار که به سمت STM32 و ST-Link هدایت می‌شود** چون یک انجمن اینترنتی گفته
  «حرفه‌ای‌تر» است — سه شب از دست می‌رود برای راه‌اندازی زنجیرهٔ ابزار، پیش از روشن شدن
  اولین LED.
- **یک پروژهٔ باتری‌محور که حول یک برد توسعه طراحی شده** که رگولاتورش در حالت بی‌کاری ۲۰
  میلی‌آمپر می‌کشد، پس آن عمر «دو ماهه» در واقع چهار روز است. مشکل هیچ‌وقت خودِ برد نبود؛
  کسی جریان خواب را حساب نکرده بود.
- **اولین PCB که با خازن و مقاومت ۰۴۰۲ و یک QFN سفارش داده شده**، با هویه دستی مونتاژ شده،
  و همان اول کار مرده تحویل گرفته می‌شود، بدون هیچ نقطهٔ تستی برای فهمیدن دلیلش.
- **شش سنسور که در جعبه‌های مخصوص فضای داخلی در مزرعه نصب شده‌اند**، با چسب‌نواری به‌جای
  گلند کابل آب‌بندی شده‌اند، و تا هفتهٔ دوم روی برد خودشان بخارآب می‌بندند.

## نصب

**گزینهٔ الف — یک فایل.** فایل [`embedded-iot-mentor.skill`](./embedded-iot-mentor.skill)
را دانلود کنید و در Claude باز کنید. (ذخیرهٔ Skill باید برای حساب یا سازمان شما فعال باشد.)

**گزینهٔ ب — Claude Code.** آن را در پوشهٔ skills خود باز کنید:

</div>

```bash
python package_skill.py --install                                     # برای کاربر شما
python package_skill.py --install --skills-dir <repo>/.claude/skills  # فقط برای یک پروژه
```

<div dir="rtl" align="right">

یا اگر بستهٔ آماده را دارید و نسخه‌ای از این مخزن را ندارید:

</div>

```bash
python package_skill.py --install-from embedded-iot-mentor.skill
```

<div dir="rtl" align="right">

یا دستی — یک فایل `.skill` چیزی جز یک zip نیست:

</div>

```bash
mkdir -p ~/.claude/skills && unzip embedded-iot-mentor.skill -d ~/.claude/skills/
```

```powershell
# ویندوز: Expand-Archive جز پسوند .zip چیزی نمی‌پذیرد، پس اول از یک کپی نام‌گذاری‌شده استفاده کنید
New-Item -ItemType Directory -Force "$HOME\.claude\skills" | Out-Null
Copy-Item embedded-iot-mentor.skill "$env:TEMP\embedded-iot-mentor.zip"
Expand-Archive "$env:TEMP\embedded-iot-mentor.zip" -DestinationPath "$HOME\.claude\skills" -Force
```

<div dir="rtl" align="right">

Claude Code آن را در نشست بعدی پیدا می‌کند — `/skills` آن را فهرست می‌کند، و Claude هم
هروقت یک گفت‌وگو با توضیحاتش بخواند، خودش آن را بارگذاری می‌کند.

## استفاده

فقط پروژه را توصیف کنید. مثلاً:

> می‌خواهم رطوبت خاک را در یک گلخانه ثبت کنم و روی گوشی‌ام ببینم. چند تا اسکچ Arduino
> نوشته‌ام. بودجه شاید ۱۰۰ یورو، و دوست دارم ظرف یک ماه راه بیفتد.

یا

> برای یک سنسور باتری‌خور که باید یک سال با یک باتری سکه‌ای کار کند، کدام برد؟ قبلاً فریمور
> تحویل داده‌ام، پس ساده‌اش نکن.

یا

> یک ESP32 و یک BME280 در کشوی میزم دارم. با این‌ها ساختن چه چیزی ارزش دارد؟

یا همان مورد نمونهٔ بالا:

> من کشاورزم و می‌خواهم رطوبت و نیتروژن خاک را در بخش‌های مختلف مرتعم اندازه بگیرم تا مطمئن
> شوم گوسفندهایم خوب تغذیه می‌شوند.

اگر هدف، سطح تجربه، منبع تغذیه، محیط یا زمان‌بندی هنوز روشن نباشد، چند سؤال کوتاه می‌پرسد —
و بعد به‌جای انشا، با جدول جواب می‌دهد. یک نقشهٔ کامل پروژه باید در یک صفحه جا شود؛ اگر
استدلال پشت یک انتخاب را می‌خواهید، بپرسید.

## خوب است بدانید

- **قیمت‌ها و موجودی قطعات قدیمی می‌شوند.** تخمین‌ها بازه‌اند، نه پیش‌فاکتور. قبل از سفارش،
  LCSC، Digi-Key یا تأمین‌کنندهٔ محلی خود را بررسی کنید.
- **نمی‌تواند موجود بودن قطعه را در کشور شما تأیید کند**، و این رایج‌ترین دلیلی است که یک
  نقشهٔ خوب زمین می‌ماند.
- **عمداً روی MVP متوقف می‌شود.** برای مراحل بعدی صریحاً درخواست بدهید.
- **برای کارهای ایمنی‌بحرانی نیست.** تا مرحلهٔ نمونهٔ اولیه در حوزهٔ پزشکی، خودرو یا
  سامانه‌های ایمنی کمکتان می‌کند، و بعد صریح می‌گوید توصیه‌های آماتوری کجا تمام می‌شود.

## ساختار مخزن

خودِ Skill در `embedded-iot-mentor/` قرار دارد. هرچه در ریشهٔ مخزن است، بسته‌بندی و
فراداده‌های پروژه است که Skill هرگز آن‌ها را نمی‌خواند.

| مسیر | چیست |
|---|---|
| `embedded-iot-mentor/SKILL.md` | دستورالعملی که Claude دنبال می‌کند. بیشتر تغییرها اینجا اعمال می‌شوند. |
| `embedded-iot-mentor/references/` | جزئیاتی که فقط با یک محرک خوانده می‌شوند: انتخاب MCU، ارتباطات، تخمین هزینه، چک‌لیست PCB، توان و باتری، نصب در محیط واقعی، OTA، EMC، مرز ایمنی، منابع یادگیری. |
| `embedded-iot-mentor/scripts/` | ابزارهای کوچک و قطعی، که فقط وقتی عددی مشخص خواسته شود اجرا می‌شوند. |
| `embedded-iot-mentor/examples/` | سناریوهای کامل که *شکل* پاسخ را نشان می‌دهند، برای وقتی درخواست در قالب استاندارد نمی‌گنجد. |
| `embedded-iot-mentor.skill` | **تولیدشده.** یک zip از پوشهٔ بالا — دستی ویرایشش نکنید. |
| `package_skill.py` | بسته را می‌سازد، بررسی و نصب می‌کند. |
| `embedded-iot-mentor-demo.gif` | همان ضبطی که در بالا نشان داده شده. در بسته نیست — بسته‌ساز فقط پوشهٔ Skill را برمی‌دارد. |

نگه داشتن Skill در پوشهٔ اختصاصی خودش مهم است: مشخصات فنی الزام می‌کند که `name` یک Skill با
نام پوشه‌اش یکی باشد، پس ساختن آن مستقیماً از ریشهٔ مخزن همان لحظه‌ای خراب می‌شد که کسی
مخزن را به شکل ZIP دانلود می‌کرد و `embedded-iot-mentor-main/` می‌گرفت.

## ساخت بسته

</div>

```bash
python package_skill.py          # -> ./embedded-iot-mentor.skill
python package_skill.py --check  # اعتبارسنجی منبع و بسته، بدون ساختن چیزی
```

<div dir="rtl" align="right">

فایل `.skill` یک آرشیو zip حاوی پوشهٔ Skill است — قالب آن را
[مشخصات Agent Skills](https://agentskills.io/specification) تعریف می‌کند. بسته‌ساز همه‌چیز
را زیر `embedded-iot-mentor/` برمی‌دارد، پس یک فایل مرجع جدید بدون تغییر در اسکریپت ساخت،
خودکار برداشته می‌شود. فایل‌های متنی با LF ذخیره می‌شوند و برچسب‌های زمانی zip ثابت‌اند، پس
بسته هرکه بسازد بایت‌به‌بایت یکسان است.

`--check` همان دروازه است، و CI آن را روی هر push و pull request اجرا می‌کند. وقتی شکست
می‌خورد که:

- frontmatter یکی از قیدهای مشخصات را بشکند (الگو/طول `name`، تطابق با نام پوشه، طول `description`);
- `SKILL.md` به فایلی در `references/…` یا `scripts/…` اشاره کند که وجود ندارد؛
- فایل `.skill` کامیت‌شده با پوشهٔ منبع نخواند.

مورد آخر مهم است، چون بسته در مخزن کامیت می‌شود: Skill را ویرایش کنید، بازسازی را فراموش
کنید، و آنگاه فایل دانلودی نسخه‌ای متفاوت از پوشهٔ منبع تحویل می‌دهد.

## اسکریپت‌ها

</div>

```bash
python embedded-iot-mentor/scripts/cost_estimator.py 1 4.50 "ESP32 DevKit" 10 0.12 "10k resistor"
python embedded-iot-mentor/scripts/footprint_hint.py 0603
python embedded-iot-mentor/scripts/sleep_budget.py --capacity 2000 --active-ma 80 \
    --active-ms 250 --sleep-ua 15 --interval-s 600
```

<div dir="rtl" align="right">

`sleep_budget.py` به‌جای جریان متوسط، ورودی‌های چرخهٔ کاری می‌گیرد، چون جریان متوسط دقیقاً
همان عددی است که هیچ‌کس از پیش نمی‌داند. همان فریمور، همان باتری، فقط جریان خواب از ۱۵
میکروآمپر به رگولاتور ۸ میلی‌آمپری یک برد توسعه تغییر کند: **۳٫۸ سال تبدیل می‌شود به ۸٫۳
روز.**
